*suggestions.txt*   Bottom command-line drawer with native zsh completion

SETUP                                                    *suggestions-setup*

Requires Neovim 0.11+ and zsh 5.8+ on macOS/Linux.
Fuzzy completion uses fzf (enabled by default); optional fd collects files,
with find as fallback. Missing fzf falls back to native Ex completion.
Add the plugin to runtimepath, then: >lua
    require('suggestions').setup()
<
Type :! to request native zsh completion. Right accepts history ghost text;
Alt-f accepts one word. Tab/S-Tab select a completion; Enter confirms an
explicit selection, or executes the current command when nothing is selected.
Up/Down browse prefix-matched zsh history until a completion is selected.
Esc always cancels. Ctrl-a/Ctrl-e move to start/end; Ctrl-k kills to end.

Ordinary Ex commands also show ghost text: the most recent native ':' history
entry that extends the input takes priority, followed by the first completion
that extends it. Equal or rewriting candidates are skipped. An explicit Tab
selection takes priority over history. Right or Ctrl-e accepts the ghost at
the end of the line; Alt-f accepts one word. Enter never executes unaccepted
ghost text. Empty lines, search and expression prompts show no ghost text.
Ex history uses Neovim's loaded history (including ShaDa and this session),
respects 'history' and histdel(), and skips multiline entries. Up/Down keep
native Ex history navigation when no completion is selected.

The native command line remains active: Ex ranges, substitutions, registers,
search and nested expression prompts retain Neovim semantics. :! executes
through 'shell' and 'shellcmdflag', independently of the completion backend.

CONFIGURATION                                           *suggestions-config*
>lua
    require('suggestions').setup({
      ui = { max_height = 10, max_ratio = 0.35, min_height = 3, padding = 2 },
      completion = { auto = true, debounce_ms = 70, max_results = 80 },
      fuzzy = {
        enabled = true, executable = 'fzf', timeout_ms = 2000,
        files = true, search = true,
      },
      zsh = {
        shell = 'zsh', timeout_ms = 1800, startup_timeout_ms = 6000,
        history_limit = 3000,
        -- history_file = vim.fn.expand('~/.zsh_history'),
        -- env = { ZDOTDIR = vim.fn.expand('~/.config/zsh') },
      },
      keys = { accept = '<Right>', accept_word = '<M-f>' },
    })
<
Set any key entry to false to disable that mapping. Full defaults are in
lua/suggestions/config.lua. Startup files supply compdef, fpath and aliases.
Zsh history is loaded at worker startup; session commands stay in memory. The
plugin never writes the user's HISTFILE. Completion text is read as data;
normal user-defined completion functions may still execute helper commands.

FUZZY COMPLETION                                         *suggestions-fuzzy*

Enumerable Ex contexts use fzf --filter for matching and sorting. For example,
:set rnu matches relativenumber; :help usr41 matches usr_41.txt. Custom callbacks
and Lua/expression contexts keep native completion. File/directory completion
recursively searches the nearest .git/.hg root, or the window's cwd, inserting
paths relative to that window. Special/absolute paths and wildcards use native
completion. fd respects ignore files; find skips hidden entries but ignores no
ignore files. A leading dot or /. in the query includes hidden entries, except
.git and .hg. There is no persistent file cache.

/ and ? collect unique keywords using the current buffer's iskeyword, then
fuzzy match with smartcase. Explicit \c / \C overrides case handling. Tab
selects, Right/Enter accepts, and a subsequent Enter executes. Accepted words
use literal \V search syntax, preserving explicit case modifiers. No search
ghost text is shown. The search direction remains native.

max_results limits results after fzf matching. Queries use ordinary fuzzy
matching, without extended fzf operators. FZF_DEFAULT_OPTS and its options file
are ignored. Jobs are asynchronous, cancellable, and bounded by timeout_ms per
process. Errors fall back to native Ex candidates; inspect().current.error
reports the cause. :checkhealth suggestions checks the configured executable.

fuzzy.enabled=false disables fuzzy Ex and search completion; fuzzy.files=false
keeps native file completion; fuzzy.search=false disables search candidates.
Zsh completion and history suggestions are unaffected.

COMMANDS                                               *suggestions-commands*

:SuggestionsEnable      Enable the UI and command-line mappings.
:SuggestionsDisable     Restore mappings/layout and stop the zsh worker.
:SuggestionsToggle      Toggle the plugin.
:SuggestionsReload      Restart zsh and reread its startup files and history.
:checkhealth suggestions

Reload keeps plugin options, mappings, current input and in-memory session
history. Pending completions are discarded. With automatic completion enabled,
the active command is completed again. Reload does nothing while disabled.
The worker is an interactive, non-login shell: .zshenv and .zshrc are read
according to normal zsh startup rules, but .zprofile and .zlogin are not.
Definitions made only in another running terminal are not synchronized.

The corresponding Lua functions are enable(), disable(), toggle(), reload().
inspect() reports UI state, completion state, startup output and backend errors.

NOTES                                                     *suggestions-notes*

Use only one command-line renderer. Disable Noice cmdline, wilder and
cmp-cmdline integrations before enabling this plugin. Insert-mode completion
is separate. Long input scrolls horizontally; multiline shell editing and
completion-description columns are not currently supported.

The drawer reserves cmdheight while visible and restores it on close.
The UI uses experimental vim.ui_attach and nvim__redraw APIs.
